# Star Wars FFG для Foundry V14 — русский интерфейс

Форк StarWarsFoundryVTT/StarWarsFFG 2.0.4 (upstream `4b87fe1`). Исправления совместимости адаптированы из [PR #2280](https://github.com/StarWarsFoundryVTT/StarWarsFFG/pull/2280), автор salohcin714, состояние `a3d0e66`. При переносе сохранены актуальные модели данных, исправления экипировки, импорта и создания персонажей из 2.0.4.

## Установка

Манифест для установки в Foundry:

```
https://raw.githubusercontent.com/DarkReef/StarWarsFFG/v14-ru/system.json
```

Идентификатор системы сохранён: `starwarsffg`. Установка этого форка заменяет другую установку StarWarsFFG в том же каталоге данных. Для нового мира выберите **Star Wars FFG — V14 (RU)**. Для существующего мира перед переходом с V13 сохраните резервную копию вне активного каталога данных; обратный переход требует восстановления этой копии.

Выберите русский язык в Foundry. Встроенный перевод содержит все 1103 строки исходного английского словаря и 55 дополнительных строк интерфейса. Модуль `ru-ru` рекомендуется для перевода самого Foundry; для перевода системы он не обязателен. Старые строки StarWarsFFG из `ru-ru` не перекрывают словарь форка.

Для русской сортировки навыков включите «Сортировать навыки по переведённым названиям» в настройках локализации системы. В переводе используются «ПО» (пункты опыта), «ЯМ» (ячейки модификаций), «Сила» (характеристика Brawn) и «рейтинг Силы» (Force Rating).

## Что переведено

Листы всех типов персонажей и предметов, навыки, характеристики, настройки, окно броска, управление группой, состояния, мастер создания персонажа, подсказки и сообщения. Для кириллицы добавлены системный шрифт, переносы длинных подписей и многострочные вкладки. Шрифты символов костей и значки сохранены.

В исходной системе нет компендиумов. Имена и описания импортированных предметов, талантов, видов и приёмов Силы остаются на языке исходных данных. Babele нужен для перевода этих компендиумов, а не интерфейса. В этом выпуске словари компендиумов Babele не поставляются.

## Проверка и ограничения

Выпуск 2.0.4.1402 проверен в работающем Foundry 14.368 на русском языке с модулем `ru-ru`. Пройдены 28 автоматических тестов: синтаксис 128 модулей, адаптеры эффектов и чата, перенос эффектов, правило экипировки, выбор темы, полнота словаря, сохранение подстановок и компиляция всех HTML-шаблонов (`npm test`).

В клиенте ведущего проверено открытие листов всех 6 типов актёров и 20 типов предметов без ошибок. Визуально проверены персонаж и его вкладки, миньоны, транспорт, броня и диалог броска при стандартных размерах окон в теме Mandar. Исправлены обрезанные русские подписи и конфликт темы с CSS-слоями V14.

Дополнительно пройдена 21 проверка в живом клиенте: нагрузка и экипировка сразу после подготовки данных, свободные кубики Силы и неизменность исходных эффектов, ранения и ранги группы миньонов, сохранение характеристик, включение/выключение эффектов, броски оружия, семь типов костей, сериализация и четыре режима видимости чата. Исправлены асинхронная подготовка предметов, учёт эффектов Силы и изменение модели предмета при построении карточки броска.

Выпуск остаётся предварительным: длительная игровая сессия, импорт внешних наборов OggDude/SWA, Dice So Nice и все сочетания сторонних модулей не проверялись. Перевод интерфейса достаточен для ручного ведения персонажей и бросков, но не переводит правила и импортированный игровой контент.

Сохраняется устаревший интерфейс ApplicationV1. Некоторые предупреждения Foundry об этом ожидаемы; перевод интерфейса не означает перевод технических журналов. В исходном проекте есть ошибки ESLint, поэтому общий lint отдельно сравнивается с исходной 2.0.4; они не скрываются изменением правил.

## Разработка

Node.js 24: `npm ci`, затем `npm test`. Основная ветка форка — `v14-ru`; оригинальная `main` сохранена для сравнения. Файлы Foundry, данные миров, лицензия Foundry и сторонние наборы в репозиторий не включены.

`scripts/verify-foundry-v14.mjs` экспортирует `verifyFoundryV14()` для готового GM-клиента V14. Это интеграционная проверка, её нельзя выполнить в Node: загрузите функцию в тестовом клиенте и вызовите её через разрешённую диагностику. Она создаёт одного собственного тестового актёра и удаляет его в `finally`; сообщения чата не публикуются. Проверку рендера всех листов и визуальный осмотр следует выполнять отдельно.
